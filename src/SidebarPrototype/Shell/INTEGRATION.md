# Native shell integration

Call `ShellDpi.EnablePerMonitorV2()` before creating the WPF `Application` or any window. Attach one `DesktopDockService` to the dock `Window`. `SetReservation(dockWidthDip, panelWidthDip)` registers or updates one left-edge AppBar whose width is the sum; the dock HWND itself stays dock-width wide. The panel's adjacent logical bounds are returned from `GetLayout()` for the separate panel host. Pass zero panel width in overlay mode. Call `Release()` to hide the dock and unregister the reservation; a later `SetReservation` shows and registers it again. Dispose the service on quit.

Subscribe to `LayoutChanged` and update both dock and panel window placement/size from `GetLayout()`. The panel rectangle uses the requested reserved width in split mode and the remaining primary display width when panel reservation is zero (overlay mode). Calls and event handling are expected on the attached window's dispatcher. Use `SetTopmost` for the dock's user preference. `IsFullscreenActive` tracks a foreground window covering its monitor; the service temporarily removes topmost while fullscreen is active and restores the user's preference afterward.

`GlobalHotkey` attaches to a WPF window and accepts Win32 modifier flags (`MOD_ALT`, `MOD_CONTROL`, `MOD_SHIFT`, `MOD_WIN`, optional `MOD_NOREPEAT`) plus a virtual key. `TryRegister` returns a conflict/error string. `ForegroundWindowHelper` captures/restores a foreground HWND and identifies HWNDs owned by this process. It does not install a mouse hook or consume outside clicks; the host should observe foreground changes and exempt its owned windows.

Known limits: virtual-desktop presence is not implemented; fullscreen detection is a bounds heuristic and cannot cover exclusive fullscreen or secure desktop; shell reservation is for the primary display and needs device-loss/multi-monitor validation; foreground restoration is subject to Windows focus-stealing rules. Bounds are converted from native physical pixels using the primary monitor's reported DPI; live validation at the laptop's actual display scaling is still required.
